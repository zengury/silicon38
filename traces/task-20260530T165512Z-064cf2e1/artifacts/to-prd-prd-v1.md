# PRD: 机器人车队运维监控面板

## Problem Statement
运维团队需要实时监控多台机器人的运行状态，但各机器人数据格式不统一，导致无法集中查看和快速响应异常。当前缺乏统一仪表盘、历史趋势分析和协作工具，故障排查效率低。

## Solution
构建一个统一的Web运维监控面板，支持多协议数据归一化、实时可视化、异常告警、历史分析、团队协作和配置管理，提升运维效率和响应速度。

## User Stories
1. 作为运维工程师，我希望在总览仪表盘上看到所有机器人的关键指标概览（电量、温度、CPU、网络延迟），以便快速掌握整体健康状态。
2. 作为运维工程师，我希望仪表盘包含环形图展示电量分布、折线图展示CPU/温度趋势、热力图展示地理位置分布，以便多维度分析。
3. 作为运维工程师，我希望系统能自动检测机器人摔倒、关节失联、电量过低等异常并发出告警，以便及时处理。
4. 作为运维工程师，我希望查看每台机器人的30天历史曲线（电量、温度、CPU、网络延迟），以便分析长期趋势。
5. 作为运维工程师，我希望在配置面板中自定义告警阈值、采样频率和重连策略，以便适应不同场景。
6. 作为运维工程师，我可以在面板上留言、@同事、标记“我在处理”，以便团队协作。
7. 作为运维工程师，我希望导出当前视图或报表为PDF/Excel，以便汇报和存档。
8. 作为运维工程师，我希望面板支持暗色/亮色主题切换、多语言（中文/英文）和可拖拽布局，以便个性化使用。
9. 作为系统管理员，我希望数据归一化模块能自动适配不同机器人协议（如JSON、Protobuf、Modbus），以便接入新机器人无需修改核心代码。

## Implementation Decisions
- **数据归一化层**：设计适配器模式，每种机器人协议实现一个Adapter，输出统一内部Schema（字段：robot_id, battery_level, joint_temperatures, cpu_usage, network_latency, task, gps, status, timestamp）。
- **后端架构**：使用Node.js + Express，WebSocket推送实时数据，PostgreSQL存储历史数据，Redis缓存最新状态。
- **前端架构**：React + TypeScript，使用ECharts或D3.js实现图表，拖拽布局使用react-grid-layout，国际化使用react-i18next。
- **告警引擎**：规则引擎，支持阈值告警（电量<20%）、状态告警（摔倒、关节失联），可配置静默期和升级策略。
- **协作功能**：基于WebSocket的实时留言板，支持@提及和标记状态。
- **导出功能**：后端生成PDF（使用Puppeteer）和Excel（使用exceljs）。
- **主题**：CSS变量实现暗色/亮色切换。
- **多语言**：i18n资源文件，支持中文和英文。

## Testing Decisions
- **测试原则**：只测试外部行为，不测试实现细节。使用Jest + React Testing Library。
- **测试模块**：数据归一化适配器（单元测试）、告警引擎（单元测试）、API端点（集成测试）、前端组件（组件测试）。
- **先例**：参考项目中已有的测试模式，如`/tests`目录下的单元测试和`/cypress`中的E2E测试。

## Out of Scope
- 机器人固件升级管理
- 机器人远程控制（如移动、停止）
- 多集群联邦管理
- 移动端原生应用（仅Web响应式）
- 第三方系统集成（如工单系统）

## Further Notes
- 初始支持10台机器人，后续可水平扩展。
- 数据归一化适配器需支持热插拔，新增协议只需添加新Adapter。
- 告警通知方式初期仅面板内通知，后续可扩展邮件、短信。
