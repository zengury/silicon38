## 1. 用户画像 (Persona)

### Persona A: 张伟 — 一线运维工程师

| 维度 | 描述 |
|------|------|
| **年龄** | 28 岁 |
| **经验** | 3 年机器人运维经验 |
| **技术能力** | 中高（熟悉 Linux 命令行、能读 JSON 日志、不会写代码） |
| **工作环境** | 7×24 运维中心，三屏工作站，暗色环境 |
| **核心目标** | 快速发现异常机器人 → 诊断原因 → 决定是否需要现场介入 |
| **痛点** | 切换 4-5 个工具才能看清全貌；告警信息被淹没在日志里；同事不知道我已经在处理某台机器 |
| **使用频率** | 每日 8 小时轮班，面板始终开在主屏幕 |
| **关键时刻** | 凌晨 3 点独自值班，3 台机器人同时告警，需要最快判断优先级 |

### Persona B: 李梅 — 运维主管

| 维度 | 描述 |
|------|------|
| **年龄** | 35 岁 |
| **经验** | 8 年自动化运维，2 年机器人车队管理 |
| **技术能力** | 高（能写脚本、配告警规则、分析趋势） |
| **核心目标** | 了解车队整体健康趋势 → 优化维护计划 → 生成周报 |

## 2. 核心用户旅程 (Journey Maps)

### Journey 1: 告警发现 → 诊断 → 响应 (The True Act)

```
┌──────────────────────────────────────────────────────────────────┐
│ 时刻              │ 行为                    │ 触点               │
├──────────────────────────────────────────────────────────────────┤
│ T+0s              │ 机器人摔倒，遥测上报     │ 数据网关           │
│ T+1s              │ 告警引擎触发，WebSocket  │ 告警引擎           │
│                   │ 推送 CRITICAL 告警       │                    │
│ T+2s              │ 面板弹出红色告警卡片，   │ 仪表盘主屏         │
│                   │ 伴随声音提示             │                    │
│ T+3s              │ 工程师点击告警卡片       │ 告警弹窗           │
│ T+4s              │ 面板自动跳转到该机器人   │ 机器人详情面板     │
│                   │ 详情，高亮异常指标       │                    │
│ T+5-10s           │ 工程师查看关节温度和     │ 详情面板+历史曲线  │
│                   │ 历史曲线，确认摔倒前     │                    │
│                   │ 左膝温度异常              │                    │
│ T+12s             │ 工程师点击「我在处理」   │ 协作面板           │
│                   │ 并留言 "@现场组 3号机     │                    │
│                   │ 摔倒，左膝需检查"         │                    │
│ T+15s             │ 现场组收到通知，前往     │ (外部通知系统)     │
│                   │ 处理                      │                    │
│ T+5min            │ 机器人恢复在线，告警     │ 仪表盘             │
│                   │ 自动解除                 │                    │
│ T+6min            │ 工程师标记告警「已处理」 │ 告警历史列表       │
│                   │ 填写备注「左膝电机更换」 │                    │
└──────────────────────────────────────────────────────────────────┘

设计要求:
- T+0s → T+2s: 告警延迟必须 < 2 秒，声音提示要足够明显但不刺耳
- T+4s: 从告警卡片到机器人详情的跳转需一次点击
- T+12s: 「我在处理」按钮必须在详情面板最显眼位置
- T+6min: 「已处理」按钮 + 备注框在告警列表中内联展开
```

### Journey 2: 日常监控 — 一眼判断车队状态

```
工程师到岗 → 打开面板 → 扫一眼总览仪表盘（环形图+车队网格）
→ 看到 48 台绿色（正常），1 台黄色（WARNING：电量 22%），1 台红色（CRITICAL：离线）
→ 点击红色机器人 → 看详情 → 判断 3 分钟前掉线 → 派人检查
→ 点击黄色机器人 → 确认正在充电 → 忽略
→ 关闭详情，回到总览

设计要求:
- 颜色编码必须一目了然：绿色=正常，黄色=警告，红色=严重，灰色=离线
- 环形图显示「48/50 正常」比例
- 异常机器人自动排在网格顶部
```

### Journey 3: 报表生成 — 周会准备

```
李梅周一早上 → 打开面板 → 点击「导出报表」
→ 选择时间范围「上周」、选择「全部机器人」
→ 选择格式 PDF → 生成 → 下载
→ 报表包含：车队可用率、告警统计 Top 5、电量趋势、温度异常汇总
→ 发送到部门群

设计要求:
- 「导出」按钮在总览面板顶部工具栏，不隐藏
- 时间范围预设：今天/昨天/本周/上周/过去 30 天/自定义
- 导出过程显示进度条，大车队 > 30 秒
```

## 4. 交互设计决策

### 4.1 告警优先级可视化
| 级别 | 颜色 | 动画 | 声音 | 自动解除 |
|------|------|------|------|----------|
| CRITICAL | 红色 (#E53E3E) | 脉冲边框 + 弹窗 | 短促蜂鸣 (可关闭) | 否（需手动标记已处理） |
| WARNING | 黄色 (#DD6B20) | 静态高亮 | 无 | 是（指标恢复正常后自动消除） |

### 4.2 机器人卡片设计
```
┌──────────────────────┐
│ ● R03  工业区-A       │  ← 状态点 + 机器人ID + 位置
│ ⚡ 78%  🔥 42°C       │  ← 电量 + 最高关节温度
│ 🧠 35%  📶 12ms       │  ← CPU + 网络延迟
│ 📋 巡检任务-3          │  ← 当前任务
│ 🚨 1 条未处理告警      │  ← 仅在有告警时显示
└──────────────────────┘
      点击展开详情 ↓
```

### 4.3 拖拽布局约束
- 预设 3 种布局模板：标准（3 列网格）、宽屏（4 列）、紧凑（2 列大字）
- 用户自定义布局保存在 localStorage
- 「重置布局」按钮始终可见
- 最小卡片尺寸 300×200px，防止内容不可读

### 4.4 暗色/亮色主题
- 暗色为主题默认（运维环境标准）
- 亮色主题备选（白天办公室使用）
- 图表色板同时切换：暗色用高对比度色、亮色用柔和色
- 切换动画 300ms ease-in-out

### 4.5 国际化优先级
- Phase 1: 中文（默认）+ 英文
- 所有 UI 文案、告警信息、日期格式均需 key 化
- 数字格式跟随语言（zh: 万/亿, en: k/M）
- Phase 2: 日文、韩文（按需）

### 4.6 响应式策略
- 最小支持分辨率: 1366×768（运维中心常见旧显示器）
- 推荐分辨率: 1920×1080 及以上
- < 1366px 时不保证体验（运维面板不是移动端产品）

## 5. 设计原则 (从 soul.md 汲取)

| 原则 | 在面板中的体现 |
|------|---------------|
| **Light is data. Design backward from arrival, not forward from what you hold.** | 告警先到达工程师眼前，再提供深入工具。面板的信息架构是从「被通知」倒推设计的，不是从「数据源」正推的。 |
| **The depth of the module is where the two are reconciled, out of sight.** | 数据归一化层对工程师完全不可见。他们只看到统一格式，不需要知道 adapter 的存在。 |
| **Remove until only the true act remains.** | 默认总览只显示：状态点 + 电量 + 温度 + 告警数。其他指标折叠在详情中。每个新增指标都要问：它服务于「判断故障」还是分散注意力？ |
| **The one true act: in the seconds a machine is failing: which one, what's wrong, how long is left, what to do.** | 告警弹窗必须在一屏内回答这 4 个问题。不需要滚动，不需要切换页面。 |

## 6. 组件库存 (Component Inventory)

以下组件需要 UI Design System 产出：

### 核心组件
1. **RobotCard** — 机器人摘要卡片（网格/列表两种模式）
2. **AlertBadge** — 告警计数徽章
3. **AlertBanner** — CRITICAL 告警弹窗条
4. **StatusDot** — 在线/离线/警告/错误状态点（脉冲动画）
5. **MetricRing** — 环形图（电量、健康度）
6. **TrendLine** — 折线图（时序趋势，支持缩放）
7. **FleetHeatmap** — 地理热力图
8. **RobotDetailPanel** — 机器人详情侧边/底部面板
9. **HistoryChart** — 30 天历史曲线（多指标叠加）
10. **ThresholdSlider** — 告警阈值滑块（范围 + 当前值标记）
11. **ConfigForm** — 配置表单（采样频率、重连策略）
12. **CommentThread** — 留言线程（支持 @mention）
13. **ClaimButton** — 「我在处理」按钮（状态切换）
14. **ExportDialog** — 导出对话框（时间范围、格式、机器人筛选）
15. **ThemeToggle** — 主题切换开关
16. **LangSwitch** — 语言切换下拉
17. **DragHandle** — 卡片拖拽把手
18. **NotificationBell** — 通知铃铛（未读计数）

## 7. 边缘情况 & 错误状态

| 场景 | 处理方式 |
|------|---------|
| 某台机器人 15 秒未上报 | 状态切为 OFFLINE，卡片变灰，显示「最后在线: X 秒前」 |
| WebSocket 断开 | 顶部显示黄色横幅「连接已断开，正在重连...」+ 自动重连（指数退避，最大 30s） |
| 历史数据查询超时 | 显示部分数据 + 提示「查询超时，仅显示最近 7 天数据，点击重试」 |
| 导出大报表（> 30s） | 异步任务模式：提示「报表生成中，完成后通知您」→ 生成完毕通过通知铃铛提醒下载 |
| 同一机器人被两人同时认领 | 先到先得，第二人看到「已被李梅认领 (2 分钟前)」 |
| 阈值设置为无效值 (如负数) | 表单内联校验，红色提示「阈值必须 > 0」 |
| 地图加载失败 (内网无外网) | 显示占位地图 + 文字坐标列表，降级可用 |
