# UX Design Spec: 机器人车队运维监控面板

---

## 1. User Persona — 运维工程师 张工

### Profile

| Dimension | Detail |
|---|---|
| Name | 张工 (Zhang Wei) |
| Role | 中级运维工程师，机器人车队运维组 |
| Age | 29 |
| Experience | 4 年运维，1.5 年机器人运维 |
| Tech Proficiency | 高 — 熟练使用 CLI、脚本、监控系统 |
| Work Context | 办公室桌面（双显示器，2560×1440），偶尔笔记本远程 |
| Shift | 正常班 + 每周 1 次 On-call |
| Team Size | 同组 4 人，同时在线 2-3 人 |

### Goals

1. **10 秒判断车队状态** — 扫一眼仪表盘就知道有没有问题
2. **快速定位故障机器人** — 从告警到机器人详情 ≤ 3 次点击
3. **协同无冲突** — 知道哪位同事在处理哪台机器人
4. **配置可追溯** — 谁改了哪台机器人的阈值，什么时候
5. **报表一键生成** — 周报不需要手动截图拼接

### Frustrations

- "现在的告警太多，狼来了效应——真正的紧急告警淹没在一堆 warning 里"
- "每台机器人数据格式不一样，我每天花 30 分钟手动转格式"
- "我在修一台机器人时，同事不知道，也在同时操作，配置互相覆盖"
- "老板要周报，我要手动截 20 张图贴到 PPT 里"

### Behavioral Patterns

- 打开面板先看总览 → 发现有异常 → 点进机器人详情 → 看曲线定位时间点 → 评论/标记处理
- 配置更改后习惯等 5 秒确认同步成功
- 习惯用快捷键（期望 Tab 切换、Enter 确认、Esc 关闭）
- On-call 时移动端看告警，但实际操作还是回到桌面

### Journey 1: 发现并处理故障

```

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

             + 折线图        → 跳转详情         + 关节状态       "我在处理"         清除标记
Emotion:     😌 平静         😰 紧张            🧐 专注          🤝 协作            😌 放心
Pain:        数据太密        声音太吵           历史加载慢        同事不看评论        没自动恢复检测
            看不清趋势      连续告警轰炸        曲线无标注        不知道谁在处理

                                                              显式标记             + 通知

### Journey 2: 调配置

```
Stage:      发现问题阈值不合理  →  打开配置面板  →  修改阈值    →  下发确认    →  验证生效

                                    或数值输入     并下发                      数据点

Pain:        不知道之前          配置项多         不知道          同步超时        旧的告警仍
            谁设的阈值          找不到想改的      合理范围        无反馈         在响
Oppty:       显示修改历史         分组+搜索        显示推荐值      3 秒超时+       确认后自动
            + 修改人             默认值提示        实时预览        手动重试        dismiss
```

### Journey 3: 导出周报

```
Stage:      选择范围       →    生成报表      →    下载
Touchpoint:  报表页面          进度指示器           通知 + 下载链接
Action:      选时间范围        点击"生成"           点击下载
            选机器人范围      后台执行

            哪些参数          无进度反馈            老板要的图表没包含
Oppty:       预设模板         实时进度条            预览 + 自定义模板
            "本周报告"        后台执行不阻塞

## 5. Interaction Patterns

### 5.1 布局系统

| 特性 | 实现 |
|---|---|
| 导航 | 左侧固定导航栏，图标 + 文字，当前页面高亮 |
| 总览仪表盘 | 可拖拽网格 (react-grid-layout)，4 列 × N 行，布局存到用户配置 |
| 机器人详情 | 固定两栏布局（左 60% 主内容，右 40% 地图 + 协作） |
| 配置 | 右侧抽屉 (Drawer)，宽度 400px，不遮挡主内容 |
| 响应式 | 桌面端 ≥1440px 完整布局，<1440px 压缩为单栏 |

### 5.2 实时数据展示

- 六维状态卡片：数值每秒刷新，字体颜色按阈值变化（绿→黄→红）
- 图表：ECharts 动态追加数据点，保留最近 1 小时缓存
- WebSocket 断线：卡片变灰 + "重连中" overlay，不清空已有数据
- 数据延迟指示器：底部状态栏显示"数据更新: X 秒前"，>5s 变黄，>15s 变红

### 5.3 告警交互

- 弹窗 + 声音 (Web Audio API, 可配置音量/静音)
- 弹窗位置：右下角固定，最多同时显示 3 条，超出入队列
- 去重：相同 robot_id + alert_type 在 cooldown 内不重复弹窗
- 颜色编码：🔴 emergency → 🟠 critical → 🟡 warning
- 操作按钮：确认 (ack)、静音该类型 (mute 5min)、跳转详情

### 5.4 协同标记

- "我在处理" 按钮：点击后标记，同一时间只能一人标记
- 被标记的机器人在列表和详情页显示处理者头像
- 标记超时自动释放（2 小时无活动）
- @mention 触发浏览器通知（Notification API）

## 7. Usability Heuristics Applied

| Heuristic | Implementation |
|---|---|
| **Visibility of system status** | 底部状态栏 + WS 连接指示器 + 数据新鲜度 |
| **Match between system and real world** | 机器人关节用人体关节命名 (肩/肘/髋/膝)，非技术编号 |
| **User control and freedom** | 可拖拽布局、可关闭告警、可撤销配置 |
